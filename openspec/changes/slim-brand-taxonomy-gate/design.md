# Design

## 排除清單取代逐檔計數

舊 gate 的威脅模型是「改名切換期間，某個 agent 把舊名寫回 active code」。切換已完成，現在真正會發生的只有一種：agent 讀到舊文章或舊 prompt，把 `ClawdNote`／`SP-123` 之類寫回新內容。這只需要「新出現的舊名會被擋」，不需要知道每個合法殘留在每個檔案出現幾次。

刻意保留舊名的地方很固定：redirect 實作與對照表、拒收舊名的驗證器、測試 fixture、歷史紀錄（`sources/`、`openspec/`、`scores/archive/`）、逐字引用的修稿回饋。這些用路徑排除就夠了。代價是排除檔案裡新增的舊名不會被擋；這些檔案本來就是在處理舊名，風險可以接受。

## 取捨

- 舊 spec 規定 active code／docs 不得整個目錄排除；這次 `tests/` 會整個排除。測試裡的舊名幾乎都是「確認舊名會被拒收」的 fixture，逐條記帳的成本大於它防的東西。
- 只看語意明確的 pattern（`SP-123`、`sp-123-`），不看裸 `SP`／`CP` 字串，跟原規格一樣，避免誤傷。
