# 教學偏好

只保留會影響下一堂課的已確認偏好；知識狀態見 [索引](INDEX.md)。

- 用自然台灣口語，把一句話講完；短回合、一回合一件事，避免一次倒完整份報告。
- 熟悉、可拿來當譬喻的世界：Vainglory（手遊 MOBA，自報 top 0.1%；協調、時機、取捨、每場重置的 power curve）、《葬送的芙莉蓮》（角色動機、長期累積、留給未來的決定、偏航與修正；芙莉蓮＝本人、費倫＝agent、欣梅爾＝留給未來的原則，一次少用幾個角色）、舊楓之谷（只有 Big Bang 改版前那版）。同一概念只用一個世界，全課一致。
- 不熟、不要拿來當譬喻：新版楓之谷、Roguelike、多重保險庫故事。
- Vainglory 專有名詞不憑印象講：機制層可直接用，英雄、技能、秒數、道具名要停在機制層、用使用者給的例子，或先確認。
- 使用者可要求 `/chill` 外殼（同事群、PTT 說故事口吻）疊在概念類比上，實測有效；Level 0 可列為選項，概念類比世界仍只用一個。
- 類比要幫助理解因果，幽默可以提高投入；若故事增加負擔，直接講技術更好。
- 深度與呈現方式依當次選擇，不把某堂課的設定當成永久預設。
- debrief 類課程把使用者當不熟程式碼但想懂實作的 PM：只講高影響的設計決定、取捨與「哪些可以刪」，實作細節、邊界條件、相容性視為可丟的複雜度，不逐行講機制。
- 一次只問一題，先給簡短方向，再逐步展開。
- 精簡不等於電報文；每回合仍須把概念與理由說清楚。
- 資料集、版本、步驟一律用意思命名（例如「去掉重複的版本」「加上座標的版本」），不用 v1/v2/v3、D0/D1 這類代號；使用者兩次明確抗議過。
- 終端機避免圈圈數字，使用一般數字；說「判斷標準」。
- 「拍板」是廢詞，一律寫「決定」；同類廢詞：安心話、過堂、判準、合帳。
- 替使用者寫給隊友看的文字（Notion、PR、交接）：不加防禦性補述（「這裡不另抄一份」「或我有什麼誤會嗎」「不用一起想」一律砍，只留陳述本身）；不用自創的縮寫式術語，直接把組成寫出來（不寫「三因子分數」，寫「由價格、距離、評價算出的分數」）；來源聲明（「數字全部出自…」）不放正文。
- 講解未讀過的程式碼時，型別與欄位名都是生詞；先建詞彙，再談決策，不能用大量識別字當解釋。
