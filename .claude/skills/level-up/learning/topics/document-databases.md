# 文件資料庫（Firestore）

狀態：`familiar`（情境判斷；實作尚未驗證）

## 證據

- 能推出反正規化的代價：同一份資料重複存在多份文件，修正時每一份都要各自改，資料庫不會自動同步。
- 自行推出批次修正的流程（讀出來、跑迴圈、寫回去），並把即時監聽連到 websocket 這類長連線；知道只推改過的那份文件。
- 能區分 Firestore 的精確比對與範圍查詢、Elasticsearch 的全文搜尋；知道 Firestore 沒有 SQL 與分組加總，可以在寫入時先算好月彙總。
- 主動追問擴充性：資料放很多年會不會撐不住、多個使用者共用同一個資料庫會怎樣。

## 下一步

親手做一次預先彙總：每寫入一筆就更新對應月份的彙總文件，並處理兩筆同時寫入同一份彙總時的衝突。
