# 規格驅動開發與多 agent 審查迴圈

狀態：`familiar（架構推理；實作尚未驗證）`

## 證據

- 能說明規格是正本、程式碼是衍生物；人的價值在定義意圖與目標，開工後才補方向通常補不回來。
- 自行推導出規格的高度：寫可觀察、換個實作仍成立的行為，函式名稱出現在規格裡是警訊。
- 自行設計「實作者＋嚴格審查者＋精簡審查者」迭代到收斂、有輪數上限、撞到設計決定才找人的迴圈，並指出收斂不等於正確：審查者要拿規格情境當評分標準，才不會和實作者一起漂離意圖。
- 能分辨何時要改規格（勝利條件改變，找人決定）、何時只是實作修正（原地修掉，不另開提案）。

## 下一步

實際跑一次：一條規格情境同時當門檻、評分標準與升級界線，看審查迴圈是否守得住。
